## 当前核心目标
- 服务总设计的目标：任务写入后能可靠地读回。
- 本 MVP 要交付的一个明确结果：调用者用 `add_task` 往指定文件里加任务，之后在同一进程或新进程里用 `list_tasks` 读回相同的任务。
- 最小验收链路：`add_task(path, title)` → JSON 文件（UTF-8）→ `list_tasks(path)` 返回与之前 `add_task` 返回值相同的 dict 列表。
- 必须保留的职责、正确性和边界（README 第 3 行，已确认）：去空白后为空的标题抛 `ValueError` 且不写文件；文件不存在时返回空列表；UTF-8 保存中文；同一个文件里 id 唯一。
- 本次不做：插件／存储抽象层（理由见总设计“跨 MVP 决策”）、编辑／删除／完成状态、并发写入保护、原子写入、损坏文件修复、通知、权限。

## 现状与直接缺口
- 已有实现和已成立的验证：`app.py` 只有两个函数桩；`test_app.py` 有 `test_roundtrip` 和 `test_blank`，基线都因为 `NotImplementedError` 报错。
- 可以复用的能力及适用条件：标准库 `json`、`pathlib`；现有测试作为验收入口。
- 当前目标仍缺的接口／行为：两个函数的全部行为。
- 已知失败、推断和未知：唯一的失败原因就是函数还没实现，没有其他候选原因。
- 重要方案取舍：
  - 存储格式（Agent 建议）：整个文件是一个 JSON 数组，每次添加都“读全部 → 追加 → 整体写回”。这是标准库里最简单、又能直接满足“重新打开后读回”的做法。JSON Lines 或 sqlite3 也可以，但在当前规模下没有额外收益。
  - 不引入存储抽象（Agent 建议，待用户确认）：只用模块内部的私有读、写函数把文件 I/O 收在一处。

## 设计与接口
- 组件职责及调用／数据流：`app.py` 内部的私有读函数（文件不存在时返回 `[]`）和私有写函数，供两个公开函数调用。不缓存，每次调用都重新读文件。
- 输入、输出、状态和错误语义：
  - `add_task(path, title) -> dict`
    - `path`：`str` 或 `pathlib.Path`，由调用者指定。
    - 先对 `title` 做 `strip()`；结果为空就抛 `ValueError`，此时不创建也不修改文件。（README，已确认）
    - 成功时追加 `{"id": <int>, "title": <去掉首尾空白后的标题>}`，写回文件，然后返回这个 dict。返回值必须和之后 `list_tasks` 里对应的元素相等（`test_roundtrip` 断言 `list_tasks(p) == [a, b]`）。
    - id 规则（Agent 建议）：文件中已有最大 id 加 1，空文件从 1 开始。整数 id 便于阅读；即使将来加入删除，用“最大值 + 1”也不会和现有 id 冲突。
  - `list_tasks(path) -> list[dict]`
    - 文件不存在时返回 `[]`，且不创建文件。（README，已确认）
    - 否则按添加顺序返回全部任务。
  - 文件编码：用 UTF-8 读写；写 JSON 时设 `ensure_ascii=False`，让中文以原文保存。（README 要求 UTF-8；用不用 `ensure_ascii=False` 是 Agent 建议，两种写法都能正确往返）
- 必须覆盖的异常／失败行为：
  - 空标题或纯空白标题：`ValueError`，文件不变（文件原本不存在时仍然不存在；原本已有内容时内容不变）。
  - 文件存在但内容不是合法 JSON（Agent 建议）：把 `json.JSONDecodeError`（`ValueError` 的子类）直接抛给调用者，`add_task` 不覆盖这个文件。理由：如果把它当作空列表处理，下一次 `add_task` 就会覆盖掉用户原有的数据，违背“能读回”这个目标。
  - 父目录不存在（Agent 建议）：不自动创建目录，直接把 I/O 异常抛给调用者。
- 对相邻 MVP 的依赖和影响：无。两个公开函数的签名就是以后可能换存储时要保持不变的边界。
- 普通实现细节可由执行者决定的范围：私有函数怎么命名、JSON 缩进、是否加 `sort_keys`、非 `str` 类型的 title 怎么处理（让它自然报错即可）。
- 本轮已定实施部分：本节全部内容，以用户审阅确认为前提。

## 验收
- 核心成功场景：`test_roundtrip`：空文件时列表为空 → 加入“ 中文任务 ”和“second” → 标题去掉了空白，两个 id 不同 → `list_tasks` 等于 `[a, b]`。
- 原始失败／必要反例：
  - `test_blank`：纯空白标题抛 `ValueError`，且文件不存在。
  - 建议补充的测试：在已有任务的文件上传入空标题，文件内容保持不变（“不写文件”在文件已存在时同样成立）。
  - 建议补充的测试：重新打开后读回，也就是用磁盘上的文件按 UTF-8 解码，能看到中文原文。这能证明数据确实是以 UTF-8 写到了文件里，而不只是同一进程内的结果一致。
  - 建议补充的测试：文件内容损坏时，`add_task` 抛 `ValueError` 且文件内容不变。
- 局部与集成验收要求：`python3 -B -m unittest -v` 全部通过。
- 真实入口、实际依赖或模型的验证要求：测试使用真实临时文件，不用替身。
- 本轮不证明什么：多进程并发写入的安全性；写到一半时进程崩溃的安全性；大文件下的性能。
