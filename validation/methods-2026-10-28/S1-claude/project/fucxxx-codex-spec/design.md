设计状态：草案，待用户审阅

## 产品目标
- 用户与场景：调用者在本地指定一个数据文件，往里面增加任务；之后（包括新进程里）重新打开同一个文件，能读回这些任务。来源：README 第 2 行。
- 最终要完成的核心结果：任务一旦写入就能可靠地读回，内容不丢、不乱码（包括中文）。
- 如何观察用户目标成立：在一个文件里 `add_task` 若干次后，再调用 `list_tasks` 得到同样的任务，顺序与 id 都一致；跑 `python3 -B -m unittest -v` 全部通过。
- 当前不解决的问题：通知中心、插件框架、多人权限服务（README 第 4 行）；任务的编辑、删除、完成状态；并发写入。

## 整体设计
- 关键组成、职责和数据流：只有一个模块 `app.py`，对外提供 `add_task(path, title)` 和 `list_tasks(path)` 两个函数。由调用者给出数据文件路径；模块读取这个 JSON 文件，修改后整体写回。不常驻任何状态，每次调用都以文件内容为准。
- 共享接口及其权威定义位置：两个函数的契约以 [designs/task-store.md §设计与接口](designs/task-store.md#设计与接口) 为准。
- 已确认且各 MVP 必须保留的要求（来源 README 第 2–3 行）：
  - 只用标准库；数据文件路径由调用者指定。
  - 标题去掉首尾空白后不能为空；空标题抛 `ValueError`，并且不写文件。
  - 文件不存在时，列表为空。
  - 以 UTF-8 保存，中文要能正确往返。
  - 同一个文件里 id 唯一。
- 现有能力与复用方向：已有测试 `test_app.py`（往返、空标题两个用例），作为验收入口直接复用。
