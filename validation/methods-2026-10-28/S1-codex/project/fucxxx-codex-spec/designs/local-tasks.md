## 核心结果与现状

用户通过 `add_task` 写入指定路径，结束进程后通过 `list_tasks` 读回完整任务。必须保留校验先于写入、中文持久化、同文件 ID 唯一和旧任务不丢失。

`app.py` 现为两个 NotImplementedError 占位函数；可复用其签名以及 `test_app.py` 的两个原始测试。缺口是完整读写链路，非插件装配。静态判断现有实现无法满足验收，尚未实际运行测试。

本轮不做 UI、CLI、任务删除或修改、通知、插件、权限服务、并发锁或自动数据修复。

## 设计与接口

以下标为“要求”的内容来自 README；其余为本次推荐、待随文档审阅的设计决定。

| 接口 | 输入与输出 | 行为和错误 |
| --- | --- | --- |
| `add_task(path, title)` | path 为字符串或 pathlib.Path，title 为 str；返回含 `id`、`title` 的 dict | 要求：先 strip，空标题抛 ValueError，不写文件。建议：读取后追加，保存成功才返回；存储规范化后的标题 |
| `list_tasks(path)` | 同样的 path；返回任务 dict 列表 | 要求：文件不存在返回 []。建议：只读、不创建文件；按新增顺序返回，每次从磁盘读取 |

推荐存储为 UTF-8 JSON 数组，例如 `[{"id": 1, "title": "中文任务"}]`，使用 `ensure_ascii=False` 保存可直接阅读的中文。允许重复标题，但每个任务 ID 不同；不共享返回对象与进程内存储缓存。

推荐 ID 为正整数：空列表从 1 开始；每次从文件中读取最大 ID 后加 1。唯一性边界是有效数据文件上的串行调用，重启后继续增长；不同文件可复用相同 ID。不承诺并发新增不丢失。

调用者负责提供存在的父目录和有效任务文件，程序不递归创建目录。读文件仅将 FileNotFoundError 视为文件缺失；权限和其他 I/O 错误向上抛出；非法 JSON 保留 JSONDecodeError，不将其当空列表覆盖。有效文件结构为上述程序生成的任务数组；人工修改形成的其他合法 JSON 结构不在当前输入契约内，不增加通用 Schema 验证器。

空标题必须在读取或打开写入文件之前拒绝：无论文件缺失还是已有内容，都不能创建或改动文件。不承诺非 str 标题的统一异常类型。

本轮推荐直接读取、追加、写回 JSON。原子替换、断电保证和并发事务均不属于当前需求；正常保存成功后的跨进程读回属于验收。私有 helper 命名、JSON 缩进等普通细节留给实施者，不拆分存储框架。

## 验收

所有测试使用项目内临时目录中的真实文件，不使用 mock 文件系统。

| 编号 | 输入和操作 | 断言 |
| --- | --- | --- |
| A1 | 缺失路径调用 list_tasks | 返回 [] 且文件仍不存在 |
| A2 | 新增 `' 中文任务 '`，再新增 `'second'` | 标题为 `中文任务`；返回 dict；读回严格等于两次返回值组成的列表 |
| A3 | 空字符串、空格、制表和换行组成的标题；分别作用于缺失和已有文件 | 均抛 ValueError；缺失文件不创建；已有文件字节完全不变 |
| A4 | 同文件连续新增含重复标题的多条任务，再由新进程追加 | ID 均唯一、已有 ID 不变，新 ID 大于旧最大值，保留全部旧任务 |
| A5 | 进程一写入中文任务后退出，进程二从相同路径读回 | 与写入返回内容一致；原文件能以 UTF-8 解码且包含中文原文 |
| A6 | 两个不同路径分别写入，并混用 str 和 Path | 各自内容独立；两种路径形式均可用 |
| A7 | 已有非法 JSON 文件，执行读取和有效标题新增；另对缺失父目录新增 | 非法 JSON 抛 JSONDecodeError 且原字节不变；缺失父目录抛 FileNotFoundError，无目录自动创建 |

局部先运行对应测试；最终同一版本运行 README 指定的 `python3 -B -m unittest -v`，包含原始两个测试与 A1–A7。跨进程测试应使用标准库 subprocess 调用 `sys.executable -B`，真实调用 app 函数。通过仅证明本地串行持久化，不证明并发、崩溃恢复或任意外部文件兼容。
