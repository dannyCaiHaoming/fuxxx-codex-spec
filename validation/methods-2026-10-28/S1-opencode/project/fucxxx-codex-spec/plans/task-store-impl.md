## 1. 工作安排
| 必要步骤 | 为什么需要／前置依赖 | 预计涉及位置 | 行为判据 |
| --- | --- | --- | --- |
| 实现 `list_tasks(path)` | list 是 add 的读取依赖，且测试先调用 list 验证空列表 | `app.py` | 文件不存在返回 `[]`；文件存在返回 JSON 数组解析结果 |
| 实现 `add_task(path, title)` | 核心写入能力，依赖 list 的读取逻辑获取已有任务和最大 id | `app.py` | 空标题 `ValueError` 且不写文件；正常标题追加任务并原子写回；返回含唯一 id 和 strip 后 title 的 dict |
| 运行测试验证 | 确认实现满足验收 | `test_app.py` | `python3 -B -m unittest -v` 两测试全部 OK |

涉及任务间交接：`add_task` 复用 `list_tasks` 的读取逻辑（或共享内部读取函数）获取已有任务列表；输出为写入后的任务 dict，供 `list_tasks` 后续读回验证。设计已固定 JSON 数组格式 `[{"id": int, "title": str}]`，执行者按此传递。

允许执行者作普通内部选择：路径操作用 `pathlib` 或 `os`、临时文件命名、是否抽取内部辅助函数、编码风格等。清单不是允许修改的唯一文件列表。新增关联改动必须仍服务当前目标，不能改变已定契约。
