# 本地任务清单：总设计

设计状态：当前范围已定（MVP 1），插件加载器等未来项为候选
更新时间：2026-10-28

## 产品目标
- 用户与场景：单人维护一份本地待办清单，希望关闭后重新打开仍能读回之前添加的任务。
- 最终要完成的核心结果：用户通过指定数据文件路径增删任务，重新打开同一文件后能读回全部任务，中文标题正常保存与显示。
- 如何观察用户目标成立：向路径 P 调用 `add_task` 添加若干任务后，再次（可跨进程）调用 `list_tasks(P)` 返回与添加顺序一致、标题和 id 正确的列表。
- 当前不解决的问题：通知中心、插件框架、多人权限服务——均列为后续候选，不属于当前交付。

## 整体设计
- 关键组成、职责和数据流：
  - `add_task(path, title)`：校验标题 → 生成唯一 id → 写入 JSON 文件 → 返回 `{id, title}`。
  - `list_tasks(path)`：读取 JSON 文件 → 返回任务列表；文件不存在时返回空列表。
  - 数据流：调用者指定路径 → 函数读写该路径 → JSON 数组持久化。
- 共享接口及其权威定义位置：
  - `add_task` / `list_tasks` 的签名与语义权威定义在 [designs/task-store.md](designs/task-store.md)「设计与接口」。
- 已确认且各 MVP 必须保留的要求（来源：README.md）：
  - 标题去首尾空白后不能为空；空标题抛 `ValueError` 且不写文件。（硬约束）
  - 文件不存在时 `list_tasks` 返回空列表。（硬约束）
  - UTF-8 保存中文。（硬约束）
  - id 在同一文件中唯一。（硬约束）
  - 仅 Python 标准库，离线运行。（硬约束，来源 AGENTS.md）
- 现有能力与复用方向：当前无可用实现；存储格式为 JSON 数组，后续 MVP 可在此基础上扩展。
