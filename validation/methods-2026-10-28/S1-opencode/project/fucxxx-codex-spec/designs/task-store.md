## 当前核心目标
- 服务总设计的目标：用户能增加任务并在重新打开后读回。
- 本 MVP 要交付的一个明确结果：`add_task` 与 `list_tasks` 完整实现，通过现有 `test_app.py` 全部测试。
- 最小验收链路：`list_tasks(新路径)` 返回 `[]` → `add_task` 添加「中文任务」「second」 → `list_tasks` 返回 `[a, b]` 且 id 不同、标题含中文正确 → 空白标题 `add_task` 抛 `ValueError` 且不创建文件。
- 必须保留的职责、正确性和边界：
  - 标题 `strip()` 后不能为空，空则抛 `ValueError`，不写文件。
  - 文件不存在时 `list_tasks` 返回 `[]`。
  - UTF-8 编码保存和读取。
  - id 在同一文件内唯一。
  - 仅 Python 标准库。
- 本次不做：插件加载器、通知中心、多人权限、并发控制、删除/更新任务。

## 现状与直接缺口
- 已有实现和已成立的验证：
  - `app.py`：`add_task`、`list_tasks` 均为 `raise NotImplementedError`。
  - `test_app.py`：`test_roundtrip`（添加后列表一致、中文、id 唯一）、`test_blank`（空标题报错且不写文件）。两测试当前 ERROR。
- 可以复用的能力及适用条件：`json`、`pathlib`/`os`、`str.strip` 均为标准库。
- 当前目标仍缺的接口／行为：写入逻辑、读取逻辑、id 生成、空标题校验。
- 已知失败、推断和未知：失败原因是存根未实现，非逻辑错误；无未知。
- 重要方案取舍及理由：
  - 存储格式选 JSON 数组 `[{"id": n, "title": "..."}]`：stdlib 直接支持，读写简单，满足当前验收。
  - id 生成选 `max(已有 id, default 0) + 1`：同一文件唯一即可，无需持久化计数器；文件被清空或不存在时从 1 开始。
  - 写入策略：`add_task` 先读已有列表 → 追加 → 原子写回（先写临时文件再替换，避免中途崩溃损坏数据）。这是最小必要的健壮性，不构成范围扩张。

## 设计与接口
- 组件职责及调用／数据流：
  - `add_task(path, title)`：
    1. `title = title.strip()`；若为空字符串 → `raise ValueError`，不触碰文件。
    2. 读取已有任务列表（文件不存在 → `[]`）。
    3. `new_id = max((t["id"] for t in tasks), default=0) + 1`。
    4. `task = {"id": new_id, "title": title}`；追加到列表。
    5. 写入文件：`json.dump(tasks, f, ensure_ascii=False, encoding="utf-8")`；用临时文件 + `os.replace` 保证原子性。
    6. 返回 `task`（`{"id": new_id, "title": title}`）。
  - `list_tasks(path)`：
    1. 文件不存在 → 返回 `[]`。
    2. 文件存在 → `json.load` 读取 → 返回列表。
    3. 文件为空或 JSON 无效：当前设计未要求处理损坏文件，属实现者可决定的边界；建议抛原始异常（不静默吞错），后续如需可扩展。
- 输入、输出、状态和错误语义：
  - `add_task(path, title)` → `dict`，含 `id`（int）、`title`（str，已 strip）。
  - `list_tasks(path)` → `list[dict]`，每项含 `id`、`title`。
  - 空标题 → `ValueError`，不创建/不修改文件。
- 必须覆盖的异常／失败行为：
  - 空白标题（纯空格/空字符串）→ `ValueError`，文件不写入（`test_blank` 验证 `p.exists()` 为 `False`）。
- 对相邻 MVP 的依赖和影响：无相邻 MVP；后续扩展（删除/通知/插件）可在此基础上加。
- 普通实现细节可由执行者决定的范围：
  - 使用 `pathlib.Path` 还是 `os` 路径操作。
  - 临时文件命名方式（在同一目录下即可）。
  - 是否用 `with` 上下文管理器等编码风格。
  - 损坏 JSON 文件的处理方式（当前不要求，实现者可选择抛异常）。
- 本轮已定实施部分：`add_task` 与 `list_tasks` 完整实现，对应验收为现有两个测试全部通过。

- 原始失败／必要反例：`test_blank` 通过——空标题抛 `ValueError` 且文件不存在。
