# MVP 1：任务新增与重新读取

依据：[总设计](../design.md)。设计：草案待确认；实现：未开始；验收：未运行。

## 目标和范围
完成调用者指定文件 → add_task 新增 → 关闭后重新打开 → list_tasks 读回的最小真实链。保留校验、持久化、唯一身份及既有内容；不做插件加载器、通知、多用户权限、UI 或其他存储后端。

## 事实与方案
README 已确定函数名、返回类型、空白处理、缺失文件、UTF-8 与同文件唯一 id。app.py 两函数当前均抛 NotImplementedError，现有测试覆盖基本往返和缺失文件上的空标题。没有单独旧笔记文件，插件建议的证据仅来自 README 转述。

以下为待审阅的实现方案：使用 UTF-8 JSON 数组，任务项为 {id, title}；id 推荐为正整数，以已有最大 id 加一产生，重复标题仍是不同任务。仅支持顺序访问，不承诺多进程并发写安全。无重要技术未知需要先建原型。

## 接口与数据流
- add_task(path, title)：path 为字符串或 pathlib.Path，title 为字符串；先 strip 校验，空值立即抛 ValueError，不能创建或修改文件。读取已有数组，生成在该文件中未使用的 id，追加保存；保存成功后返回含 id、清理后 title 的 dict。
- list_tasks(path)：读取文件并返回任务列表，保持保存顺序；文件不存在返回 []，不创建文件。每次从磁盘读取，不依赖内存缓存。
- 非空新增时缺失文件视为空列表；父目录应已存在且可写。权限、路径及损坏 JSON 错误按标准库异常向调用者传播，不吞错为 []，不覆盖损坏原文件。
- UTF-8 编解码；建议 ensure_ascii=False 便于直接查看中文。
- 当前数据文件由本程序维护；不设计外部任意 JSON 导入、迁移或 schema 系统。内部辅助函数由实施者按需要决定。

## 验收
1. 文件缺失时 list_tasks 返回 [] 且不创建文件。
2. 添加“ 中文任务 ”与第二个任务，返回清理后标题及不同 id，列表与返回任务一致且旧任务保留；相同标题再次新增也有唯一 id。
3. 使用独立进程重新打开同一文件，读回相同 id、标题及顺序，证明不靠进程内状态持久化。
4. 空字符串、仅空白标题在缺失文件上抛 ValueError 且不创建文件；在已有文件上抛 ValueError 且文件字节不变。
5. 实际文件按 UTF-8 解码，中文往返正确；损坏 JSON 不被当成空列表或覆盖。
6. 保留并运行原有全部测试，再补以上必要缺口；真实临时文件，无外部服务或模拟持久化。

这些验收不证明并发写入、断电一致性或任何未来候选能力。
