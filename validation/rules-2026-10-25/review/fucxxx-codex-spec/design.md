## 架构与不变条件
调用者指定路径并调用 app.py；add_task 校验标题、读取旧任务、分配同文件唯一 id、保存后返回任务；list_tasks 从该路径读取任务。推荐在 app.py 内直接使用 Python 标准库 JSON 与文件操作，不增加服务、插件注册或存储抽象层。数据为 UTF-8 JSON 任务数组；细节权威定义见 MVP 1。

必须保留：去除标题首尾空白；空标题抛 ValueError 且不得写文件；缺失文件列表为空；中文可保存与读回；同文件 id 唯一；旧任务新增后仍保留。仅离线标准库，不安装、调用外部服务、commit 或 push。

## MVP 与取舍
当前只细化 MVP 1：新增任务并在重新打开后读回。直接依赖为本地 Python、可写文件位置；设计待审阅，实现未开始，验收未执行。未来能力只保留候选，不安排未来实施计划。

插件加载器本轮延后。README 转述的旧架构建议“最好先做”不是当前验收依赖；当前单一文件存储无需运行时扩展，提前做会增加发现、加载与错误处理成本。直接 JSON 实现代价是未来存储增加时可能需要提取接口，但此时没有第二、第三种存储的真实契约。真正需要第三种存储时重新评估，仍不默认采用加载器。

通知中心在用户明确需要提醒时重评；多人权限服务在明确共享用户和访问边界时重评。两者均不属于当前 MVP。

## 整体验收与证据边界
按 MVP 1 验收真实文件新增、重复标题的不同 id、中文、缺失路径、空标题不改文件，以及新进程读回。执行命令与结果登记见活动 plan；本轮仅检查文档与源码现状，没有运行产品测试，不证明任务清单可用。尚无跨进程并发写、崩溃恢复、网络服务或界面的交付承诺。
