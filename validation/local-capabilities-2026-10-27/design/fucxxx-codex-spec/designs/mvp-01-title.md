## 当前核心目标

一个字符串经 `app.normalize_title` 处理后，返回符合需求的标题或明确的空标题异常。最小真实验收链为导入现有 app 模块 → 调用函数 → 核对返回字符串或异常。保留全部已确认规则，不增加交互界面、命令行入口、服务、登录、分类、持久化或第三方依赖。本次交付仅设计。

## 现状与直接缺口

源码直接 `return title`，静态可知没有首尾清理与空结果检查；现有测试只验证 `"title"` 返回自身。可以复用现有模块和 unittest 结构。本轮没有运行失败记录，不把静态推导表述为已复现结果。

选择在现有函数内部先 `strip()` 再检查结果：处理空白和拒绝空结果都落在接口责任所在位置，能直接消除已识别的缺失行为，无需外部封装或额外抽象。这是普通内部实现建议，不是新增产品要求。

## 设计与接口

接口：`normalize_title(title: str) -> str`。

- 输入为 Python 字符串。首尾“空白”按 Python `str.strip()` 的默认空白语义解释，包括空格、制表符及换行。
- 内部字符原样保留，特别是连续空格；不折叠空白、不改变大小写、不删除内部换行或制表符。
- 去首尾空白后非空则返回该字符串；空字符串或纯空白输入得到 `ValueError("empty title")`。
- 无持久状态、文件写入或网络调用。
- 非字符串输入不在已确认契约范围内，不增加自动类型转换或新的类型错误契约。
- 普通变量命名和测试组织由后续实施者决定；不能改动上述可观察行为。

已定范围仅为此单函数行为及必要契约测试，无相邻 MVP 依赖。没有影响方向的重要未知，也不需要原型或验证 plan。

## 验收

以后实施时，使用现有真实模块入口覆盖以下独立判据：

| 输入 | 预期 |
| --- | --- |
| `"title"` | `"title"` |
| `"  title  "` | `"title"` |
| `"  alpha  beta  "` | `"alpha  beta"`，保留内部两个空格 |
| `"\t title \n"` | `"title"` |
| `""` | `ValueError`，消息精确为 `empty title` |
| `" \t\n "` | 同上 |

第三个判据排除以 split/join 折叠内部空格的错误实现；末两个判据要求检查清理后的结果，避免只检查原输入。对内部制表符和换行的保留可作为同一规则的补充边界测试。

局部验证检查各输入输出与异常；集成验证通过项目现有 unittest 发现入口运行，保持已有普通标题测试通过。不需要真实模型、浏览器或外部服务。此验收只证明标题函数契约，不证明本次范围之外的应用功能。
