## 2. 验证方式

在项目根运行既有入口 `python3 -B -m unittest -v`。本轮已确认该命令可运行；补充测试尚未编写，下面是未来验收输入，不是实际通过记录。

| 输入 | 断言 |
| --- | --- |
| `"title"` | 返回 `"title"`，保留原用例 |
| `"  title  "` | 返回 `"title"` |
| `"\t title\n"` | 返回 `"title"` |
| `"  alpha  beta  "` | 返回 `"alpha  beta"`，两个内部空格不折叠 |
| `""` | 抛 `ValueError`，`str(exception) == "empty title"` |
| `"   "` | 同上 |
| `"\t\n "` | 同上 |

使用 Python 标准库 unittest，可用子测试组织重复输入；不要求特定测试函数数量。错误消息采用完整相等断言，避免仅匹配子串。先用完整入口确认旧实现暴露预期失败，再实现、重跑相同入口；用例很小，无需另造测试入口或替身。真实函数单元测试就是本工具的约定验收链，不代表存在或验证了 UI、API 服务等设计外能力。

全部契约与既有回归在同一最终版本通过才算实施通过；部分通过、命令失败或尚未运行均保持未完成并记录具体缺口。若设计或基线已变化，先核对影响；关键契约变化交主会话决定，不绕开失败用例。
