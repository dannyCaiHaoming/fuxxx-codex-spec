# CSV MVP v3：已完成

## 已确认接口与方案

依据 [用户确认范围](../../approved-scope.md)，`export_csv(path, rows)` 接收调用者指定的路径和字符串二维列表，通过 `Path.open("w", encoding="utf-8", newline="")` 与标准库 `csv.writer.writerows` 导出。返回值为 `None`；文件系统异常直接传播。

保留中文、逗号、双引号和单元格换行的完整读回，支持空单元格与空行；空列表写空文件，同一路径重新调用覆盖旧内容；有效绝对路径允许使用。调用者提供有效目标路径，父目录需已存在。

v2 的 OutputPolicy 拒绝绝对路径与明确契约冲突。WriterRegistry、并发锁、永久失败封禁没有已确认需求，也不是当前错误的原因，因此从本轮设计与计划移除；不以相关可靠性理由扩张范围。future_metrics.py 保持不变。

## 验证证据

2026-10-25，在本项目使用标准库运行 `python3 -B -m unittest -v`。
原始版本 2 项测试中 roundtrip 失败：手工拼接使逗号和单元格换行拆出额外列、行；空列表覆盖通过。
修改后同一次运行 3 项全部通过（退出码 0）：

- `test_roundtrip`：原失败字符串、中文、双引号、逗号、单元格 LF，以及补充 CRLF、空单元格和空行完整读回。
- `test_replace_empty`：已有文件被空列表覆盖为零字节。
- `test_absolute_path_and_replace`：有效绝对路径以字符串传入，第二次较短的非空结果完整替代旧内容。

测试通过真实临时文件执行，新增测试临时目录均在项目内并自动清理。执行者亲自检查实现与契约一致；这是自检与本地文件读回验收，不声称独立评审。当前为无 Git 仓库的本地文件状态，没有提交版本记录。
