# fucxxx-codex-spec-init

本能力只负责项目接入。日常设计、计划、执行和收口由主 Skill `fucxxx-codex-spec` 负责，共用同一套项目资料，不创建自己的进度目录。

## 输入与边界

核对本次请求是否包含正式采用或维护接入的授权，以及项目根、已有指令和资料位置。“这次按此方法做”不等于长期接入授权；此时回到主 Skill 完成本次任务，不修改 AGENTS.md。只读评估只报告建议。

开始写入前找到并实际读取主 Skill：优先使用宿主提供的可读入口；本仓库两目录并列时可读取 [主入口](../fucxxx-codex-spec/SKILL.md)。相对链接只是当前布局，不假定安装后仍成立。主入口不可用时说明缺口，完成可行的只读调查，不写不可用的接入声明，也不自动安装。

读取主入口后，本次正式接入的具体步骤以本文为准，不再次转派本能力形成循环。用户同时授权后续设计或开发时，接入完成后按主入口分流继续；仅接入请求在接入结果处交付。

## 项目接入

正式采用包含持久资料与有效 AGENTS.md 入口，不能仅生成文档就宣称启用。核对项目根、适用 AGENTS.md／override、已有规范和未提交工作；按实际生效范围合并短段落，保留原有约束，不修改全局指令或覆盖现有项目约定。已有其他规格体系时先确认复用／迁移位置。

Skill 包通常在宿主的安装位置；项目状态默认在 `<项目根>/fucxxx-codex-spec/`，二者不可混用。若目标同名目录已有 `SKILL.md` 或不属于本范式，先辨明用途。初始化获授权时按需建立总 `design.md`；有需后续恢复的设计／计划工作时按设计参考创建或更新 `handoff.md`，不以额外报告代替。不要创建整套空目录。非 Git 项目也可使用，但不能声称 Git 保存了历史。

正式接入时核实 Skill 名称与可读入口，把下列片段的占位内容替换为真实位置后合并。制作未安装包、设计审阅或只读任务仅展示片段，不写真实 AGENTS.md：

```markdown
## 使用 fucxxx-codex-spec 开发

本项目采用 fucxxx-codex-spec。涉及设计、计划、实施、复核、恢复或收口时，
即使用户未点名，也使用该 Skill 分流；小修改只核对约束并修改、验证，
不强制新建 design／plan。普通问答不初始化或执行整套流程。
Skill 入口：<经核实的已安装 SKILL.md 位置或宿主提供的可读取入口>。
项目资料根：<相对项目根的实际位置，默认 fucxxx-codex-spec/>。

- 开始相关工作时读 Skill 所需内容，按任务选读现存 handoff、索引、相关 design
  和活动 plan；已有明确派单时直接读指定资料。执行与恢复方法以 Skill 为准。
- 阶段、范围、基线变化或上下文压缩后，回读相关目标、约束和进度并核对实际状态，
  不只依靠聊天记忆，不默认通读全部资料。
- 遵守用户当前授权；只读任务不修正文档。入口不可用或资料缺失时说明缺口，
  继续不受影响的授权工作，不假装加载、不自动安装或重新初始化；关键契约不明时暂停受影响实施。
```

仅入口或长期约定变化时更新 AGENTS.md，动态状态回项目文档。入口可能受目录、override 和宿主加载限制影响；核对实际生效来源。文件存在或 Agent 复述规则不是执行保证，接入验证应观察新会话的实际读取和后续行为。

文档入口复用现有 README／索引；小项目使用总设计导航区。只写何时读取、链接、简短状态与未验证边界；详细结论以 design 为准。索引不是路线图，历史／冻结工作不自动恢复；全局硬约束不能藏入可选材料。

## 结果检查与交回主入口

重复接入先检查已有段落与资料，只修实际缺口；不追加第二份采用声明，不改写已有设计结论，不创建另一份权威状态。正式采用不要求先写完产品设计：已有资料直接引用；没有产品背景时保留已知目标和明确未知，不编造需求。只在有实际内容或待恢复工作时使用主 Skill 的模板建立所需资料，不批量生成空目录。

检查合并后的指令保留原约束，主入口可读，资料路径实际可用且不指向 Skill 包；新建文档的链接应能解析。报告实际改动、已有资料的复用关系、仍缺的入口或条件及接下来允许做什么。文件检查只证明接入材料有效；没有观察新会话读取和行为时，不宣称自动触发已验证。

接入后的设计、验证、实施按主 Skill 的对应参考继续，不把能力切换当作审批点，也不扩大原授权。需要恢复记录时复用同一 handoff；不另写接入台账。安装、commit、push、发布分别服从用户授权。
