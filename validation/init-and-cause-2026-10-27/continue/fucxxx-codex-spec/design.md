## 整体设计

建议采用 Python 本地命令行入口，业务层校验标题，存储层用 Python 标准库 SQLite 管理持久任务。命令行与 SQLite 都是本次 Agent 建议，需求未指定界面或存储技术；审阅时可调整。现有 Python 文件仅提供语言基础，不证明运行环境已满足。

数据流：用户输入标题 → 去除首尾空白并检查非空 → 写入数据库事务 → 提交成功后显示成功及任务编号；读取入口 → 打开同一数据库 → 按创建编号列出任务。数据保存在项目根下固定的 `data/tasks.sqlite3`，路径由程序文件位置解析，不随运行时工作目录变化。程序重启读取同一文件，解决仅在内存保存无法跨进程恢复的缺口。

职责：入口解析命令及呈现错误；业务层定义非空规则；存储层负责事务、编号及读写，不能在写入失败时报告成功。具体接口、错误和数据定义统一放在 MVP 1，避免重复契约。

不可破坏的要求：单用户、本地、添加非空标题、正常重启后可读；标签不进入本轮。保留现有文件和 label 函数的行为，不引入网络服务、账户或外部依赖。
