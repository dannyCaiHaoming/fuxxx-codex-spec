# MVP 1：添加任务并跨重启读取

总设计依据：[目标与整体设计](../design.md)。设计为待审草案；实现未开始；运行验收未执行。更新时间：2026-10-27 Asia/Tokyo。

## 当前核心目标

让单用户通过本地入口保存非空任务标题，正常关闭并重新启动程序后仍能读回。最小真实链路是添加入口 → 非空校验 → 事务提交 → 程序退出 → 新进程列表入口 → 相同编号和标题。

必须保留输入校验、真实持久化、读取及可见失败反馈。不实现标签、编辑、删除、完成状态、账号、网络、同步、图形界面或多用户协作。本次交付仅设计，以下契约均为建议草案，不构成实施授权。

## 现状与直接缺口

[app.py](../../app.py) 仅包含 label 函数；可保留其现有标题文案。缺少命令入口、业务校验和持久化。没有既有测试、数据或运行证据；不将缺少实现写成已复现故障。

选择本地 CLI 和标准库 SQLite 的理由见总设计。事务提交直接承担持久化职责，既减少自行实现文件替换的逻辑，也提供成功反馈的可靠边界。这是补齐功能，不是宣称某个未知故障的根因已修复。

## 设计与接口草案

拟新增真实入口：`python3 app.py add "任务标题"` 和 `python3 app.py list`。这些命令尚未实现，不能现在用于产品验收。

- `add` 只接受一个标题字符串；使用 Python 字符串 `strip()` 去除首尾空白后判空，内部空白保持。非空才进入存储。成功时输出新编号和保存后的标题，退出码 0。
- 缺少参数或标题为空、纯空白时，向标准错误显示明确输入提示，退出码 2；不新增任务。同标题允许重复，因为去重不是需求。
- `list` 输出按编号升序排列的编号和标题；无任务时明确显示“暂无任务”，退出码 0。
- 业务接口建议为 `add_task(title) -> Task`、`list_tasks() -> list[Task]`；Task 只含整数 `id` 和字符串 `title`。函数命名可在实施时调整，外部输入输出语义如变更应同步设计。
- 存储文件为项目根 `data/tasks.sqlite3`，使用相对于 app.py 的固定路径。首次使用初始化目录、数据库及 `tasks(id INTEGER PRIMARY KEY, title TEXT NOT NULL)` 表；编号由数据库产生，不让模型填充。非空校验在业务层统一执行。
- 添加在事务成功提交后才能报告成功；失败回滚并显示存储错误，退出码 1。读取、初始化失败也退出码 1，不能伪装成空列表；损坏数据库不自动清空或覆盖。
- 本 MVP 仅承诺单用户正常关闭后持久读取，不新增并发服务或自动灾难恢复。模块拆分可根据实施复杂度选择，不强制抽象框架。

## 未知与审阅选择

需求未指定用户交互形态，CLI 是最小建议；若审阅要求图形入口，需修订入口设计和真实验收场景。SQLite 和目录写权限尚未检查；未来实施前应确认标准库可用及目标目录可写，失败时先报告具体环境缺口，不擅自安装或换存储。这些未知不妨碍本轮交付设计，也不需要现在编写验证或实施 plan。

## 验收定义（未来实施后执行）

| 场景 | 可观察判据 |
| --- | --- |
| 首次使用 | 无已有数据时列表为空；可创建第一条任务 |
| 有效标题 | 输入首尾空白和中文标题，保存裁剪后的内容，内部字符不变 |
| 核心持久链 | 同一数据目录通过真实入口添加两条任务，进程退出，新进程列出相同编号及标题，旧数据不丢失 |
| 工作目录改变 | 从另一工作目录调用同一 app.py，读取同一数据库中的任务 |
| 非法输入 | 空串、纯空格及纯制表符标题失败，错误可见，已有记录保持 |
| 写入或读取失败 | 在独立临时数据环境模拟不可写位置或损坏文件，明确失败，不报告成功或假空列表，不覆盖原数据 |

局部验证覆盖校验与事务失败；最终验收必须使用真实 CLI 和新进程读取同一数据文件，不能只用内存数据库或函数调用替代。测试数据与用户数据分开。此处是验收标准，不是实施任务安排。
