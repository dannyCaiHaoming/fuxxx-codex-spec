# 执行与恢复

按需读取：首次采用看“项目接入”；换会话看“恢复与只读边界”；委派或实施看“分派与执行”。复核、回写、收口与提交见 [复核与收口](closeout.md)；设计／计划方法见 [设计与计划](design-and-plan.md)。授权、交付终点、范围依据、提交决定等共同底线见主入口，本文不重复。

## 项目接入

正式项目接入的方法与 AGENTS.md 片段统一维护在 `fucxxx-codex-spec-init`，不在此复制。需要正式采用或修复入口时，按主 Skill 的接入分流读取该能力；临时使用和正常恢复不重新接入。AGENTS.md 仍指向主 Skill 并登记包根与阶段能力入口，动态状态继续保存于项目现有资料；恢复时这些登记是查找能力的第一来源，入口实际迁移才按维护接入授权更新。

## 恢复与只读边界

先核对用户本次范围。恢复在途工作读现存 handoff，再选读关联设计和活动 plan，检查实际代码基线、未提交差异、产物和子会话／工作区。文件状态只是线索；没有 plan 不代表未做过。

资料过期时先指出差异。维护／开发授权下由主会话修正；只读分析仅报告，不能因为“先校正状态”而写文件。handoff 缺失时检查已有资料，不自动认定首次采用；在授权内用可验证事实恢复，无法确定的状态标为未知。只要关键契约仍明确，可继续不受影响工作，不重复初始化或派单。

恢复时把现存结果分为已验证可复用、已修改待重验、未执行／受阻，核对其对应的代码和环境。任务勾选、文件存在或旧会话完成声明不是继续下一项的充分依据；在途状态不明时先查实际进程或宿主状态，不能直接重复派发。

阶段切换、基线变化或上下文压缩后，回读目标、约束和当前停点；不用加载全部历史。轻量任务只核对相关材料；需要新增设计或计划时再读设计参考。

## 分派与执行

主会话拥有设计、关键取舍、复核、整合和权威回写。子会话是独立执行上下文，不固定模型；用户可见新聊天需要对应授权，内部 Agent 遵循宿主委派规则。已有同范围授权直接沿用；无委派能力时，按主入口「结果如实」由主会话执行或说明限制。

需要委派时，按实际独立性分工；设计／代码有依赖就按依赖推进，不为并行猜接口。交接采用 plan §0，不另写同内容 brief。轻量任务没有 plan 时，直接给出目标、边界和验证要求。

交接材料必须包含：

- 实际项目／工作区、适用指令、Skill 主入口，以及执行者需要的包根或阶段能力入口；按子会话可解析的位置给出，不把主区相对布局当成通用路径。
- 相关设计与活动 plan 的路径、版本；当前目标、已定范围和验收。
- 任务代码基线及必要未提交依赖，区别本轮新增差量和已有工作。
- 环境、成本、外部操作授权和停止点；交付与证据位置。

未提交设计和依赖要实际提供，不能假设从 HEAD 创建的工作区已经包含它们。无 commit 时可用相关文件快照／差异及必要 hash，不建立全仓清单。路径按真实工作区解释，不把主区绝对路径当成子区可写位置。

独立执行上下文不等于独立工作区。派单时在 plan §0 的执行边界／交付位置或轻量任务原交接中明确实际写入归属：

- 独立工作区：子会话在自己的 plan 副本或已有证据位置保存结果和回写建议，返回主会话；子区设计和 handoff 副本不成为主区权威状态。
- 共享工作区：明确每个执行者可写的文件或结果位置；同一 plan 指定一名维护者，其余执行者返回结果或写指定证据位置，由维护者汇总。修改范围冲突时按顺序执行，不让多个执行者同时回写同一文件，不强制新增 worktree 或账本。

主区总设计、子设计和 handoff 均由主会话统一回写，子会话不直接修改。主会话维护需跨会话跟进的活动表、负责人、工作区、任务依据和状态；直接执行时也由主会话维护这些记录。并发主会话先确定当前协调者，不引入锁服务。

执行者实际读指定设计和存在的 plan；无 plan 任务核对明确交接。开工前核对直接任务间的接口产出与消费，执行时将真实输出与计划判据比较：

- 与预期相符：保存必要结果，继续下一项依赖已满足的工作。
- 实现错误：保留失败输入和环境，按下文方法定位，不改判据制造通过。
- 计划错误：接口名、命令或步骤与权威设计冲突时，在既定契约内作最小纠正；按写入归属由计划维护者同步理由及受影响后续任务，不能只口头绕过。设计契约本身需变化时按暂停与恢复规则处理。
- 证据不足／环境受阻：说明未能验证什么，不能当作程序失败或完成；继续不受影响部分。

计划服从用户已确认的设计，设计本身也以主入口「范围依据」为准。只记录影响后续执行的决定，不逐步新增账本。

已有开发完成授权且条件具备时，主会话按主入口「交付终点」连续推进当前交付所需的设计、计划、实施、复核、整合和收口；普通纠错、必要调查和授权内的有界验证照常继续。完成本次交付后停止扩展，下一 MVP 需要新的授权。

需要暂停的情况及处理：

- 到达用户指定的审阅或交付边界：交付当前成果，记录仍需恢复的工作；不能因“连续推进”越过边界。
- 需要实质改变目标、产品／共享契约、验收或成本范围：子会话报告证据、影响与选项，暂停受影响操作。主会话核对已有决定与授权；已有明确决定直接落实，仍需用户选择或补充授权时才询问。
- 关键契约仍不明、必要权限／环境缺失或已到约定投入边界：保存实际进度，说明阻塞、恢复前提和下一项有价值的动作；继续不受影响的授权工作，不猜契约、不自行扩预算或无限重试。

目标或契约变化获确认后，由主会话先更新受影响的权威设计，再同步活动 plan 的依据、任务和验收，保留有效执行结果并标明需要重验的部分；同步 handoff 中受影响的停点和下一步。通知相关执行者读取更新后的依据、核对实际基线后，才恢复对应执行。没有 plan 时更新原交接即可，不补造计划或重写无关文档；决策未落实到执行依据前不能沿旧计划继续。

任务完成或发生重要变化时，及时在指定位置保存结果并返回状态，由 plan 维护者及主会话同步相应执行记录和 handoff；不把持久化全部留到最后。轻量任务可直接返回差量和验证结果，不强制额外文件。

主会话按需读取紧凑状态，完成或出现实质问题时看详情，不高频轮询。缺少自动唤醒能力时不承诺无人值守跟进。跨聊天发送遵循宿主权限；不能主动发送时由主会话读取状态。

子会话返回：实际结论与证明层次；差量／产物位置和基线；验证证据及未知；设计差异与回写建议；仍在运行或需保存／清理的资源。任务完成后等待复核，不自行开始下一 MVP；主会话继续完成同一授权范围内后续工作。
