# fucxxx-codex-spec

以当前交付目标为准：总 design 提取 MVP，plan 安排必要工作，执行证据经复核回补设计。项目文件支持恢复，不能替代真实代码、运行状态和验证结果。

## 先确定本次任务

用户明确要求采用本 Skill，或有效项目指令已声明采用且本次属于相关开发工作时，进入以下分流。触发表示使用这套方法判断和推进，不表示自动生成全部文档或获得整项目实施授权。

核对项目根、适用指令、已有资料及相关未提交改动。采用项目已确认的资料路径；默认资料根为 `<项目根>/fucxxx-codex-spec/`。**本 Skill 包与项目资料目录用途不同**，不要在包内写项目进度；同名目录冲突时先辨明用途，不覆盖内容。

| 当前请求 | 处理与按需阅读 |
| --- | --- |
| 首次采用、项目接入 | 读 [协作与收口](references/collaboration-and-closeout.md) 的“项目接入”；有初始化授权才合并 AGENTS.md 入口、建立资料。 |
| 设计、MVP、计划或方案验证 | 读 [设计与计划](references/design-and-plan.md)；只创建或更新当前需要的文档。 |
| 实施、委派、复核、恢复、收口 | 读 [协作与收口](references/collaboration-and-closeout.md) 的对应部分，再读取指定设计和存在的活动 plan。 |
| 小修复、文案或简单配置 | 核对相关约束后直接修改、验证。需要设计决策或交接时才读对应参考，不强制新建 MVP、plan 或子会话。 |
| 只读分析、审阅 | 选读相关参考与项目证据，只报告结论；发现资料过期也不顺手修正。 |
| 普通问答 | 直接回答，不初始化资料或执行完整流程。 |

先确定本次交付终点：只审阅就只读；只写设计／计划就在文档边界交付；要求开发完成且授权充分时，连续完成必要设计、计划、实施、验收和收口，不因写完一份文档或子会话返回而自动停工。已有资料直接复用，简单任务走轻量路径，不预写未来全部 MVP 的计划。阶段切换时按上表读取下一阶段参考，具体暂停与恢复条件见协作参考“分派与执行”。

已读取且仍适用的内容无需重复加载。创建资料服从当前请求范围；采用 Skill 不另行授予安装或调用外部服务的权限。用户仅要求草案、制作包或验证时，在相应边界交付，不自动安装或在业务项目启用。

## 从正确位置继续

- 恢复在途工作：读现存 `handoff.md`，按索引选读总 `design.md`、当前子设计和活动 plan；已有明确派单时直接读指定资料并核对基线。
- handoff 缺失时先查已有资料，不能据此判断首次采用。状态与实际冲突时指出差异；只有本次含维护／开发授权才修正。关键契约无法确定时暂停受影响实施，继续不受影响部分。
- 阶段、范围、代码基线变化或上下文压缩后，回读当前目标、约束和进度，并核对实际差量与会话状态；不默认通读全部历史，不重复派单。
- 执行以当前 MVP 已定范围为依据。每项新增工作应直接服务当前验收、必要依赖或已确认约束。未来增强保留为候选／延后；MVP 不能删掉已确认职责或降低验收。
- 用户最新要求若改变目标或契约，先明确其对设计和计划的影响；普通范围内实现选择自行处理，重大取舍交主会话／用户，不在代码里偷偷改约定。

## 信息放在哪里

| 位置 | 负责内容 |
| --- | --- |
| 有效 AGENTS.md | 采用声明、Skill／资料入口、读取与恢复要求；不放本轮进度。 |
| 现有 README／索引或总设计导航区 | 何时读取、链接、简短状态和验证边界；不重复设计全文。 |
| `design.md` | 整体目标、架构、不变条件、MVP 关系与能力摘要。 |
| `designs/` | 各 MVP 的范围、接口、未知、验收及最终结论。 |
| `plans/` | 临时验证／实施安排及执行结果，不另定设计契约。 |
| `handoff.md` | 主会话维护的当前焦点、活动工作、阻塞和下一步。 |
| 已有证据位置或 `evidence/` | 支撑结论的必要记录；复用既有测试／CI／报告，不囤积全部日志。 |

模板按需使用：[总设计](assets/master-design.template.md)、[MVP 子设计](assets/mvp-design.template.md)、[Plan](assets/plan.template.md)、[Handoff](assets/handoff.template.md)。它们是可裁剪的内容契约，不是必须填满的表单；替换占位内容与路径，保留当前目标、范围、验收和证据边界。

## 执行与交付底线

主会话负责设计、关键取舍、复核、整合及权威回写；子会话在指定位置交付结果，不修改主区权威设计或 handoff。独立上下文不代表独立工作区，按协作参考明确实际写入归属。派单、读取或自报完成均不等于实际验收。需要委派时遵循用户和宿主授权；无能力时主会话执行或说明限制，不虚构子会话状态。

存在 design／plan 或委派工作时，依照协作参考完成复核、设计回写、索引同步、结果保存、已结束 plan 移除及安全清理。轻量任务只更新实际受影响记录。通过、部分通过、失败与未知分别报告；不得用子区测试通过替代主区集成结果。

commit、push、发布相互独立。已有决定按授权执行；明确暂不提交时保留本地，不重复催问；尚无决定时在相关开发收口后询问。只写设计／计划的任务不顺带实施或主动要求提交业务项目。

本包依据设计草案 v0.4 提炼，核心方法自包含；不要求安装或自动串联 Superpowers。
