# fucxxx-codex-spec-init

本能力只负责项目接入。日常设计、计划、执行和收口由主 Skill `fucxxx-codex-spec` 负责；本能力按主入口「资料归属」共用同一套项目资料。

## 输入与边界

核对本次请求是否包含正式采用或维护接入的授权，以及项目根、已有指令和资料位置。“这次按此方法做”属于临时使用，不等于长期接入授权：回到主 Skill 完成本次任务，AGENTS.md 保持原样。只读评估只报告建议。

开始写入前，按主入口「能力读取」找到并实际读取主 Skill；本仓库内可读 [主入口](../fucxxx-codex-spec/SKILL.md)。主入口不可用时按「缺口处理」报告，并完成可行的只读调查。这种情况下不写接入声明：没有可读入口的采用声明会让后续会话误以为方法已生效。

读取主入口后按本文完成接入，再按「阶段衔接」交回：用户同时授权后续设计或开发时继续分流，仅接入的请求在接入结果处交付。

## 项目接入

正式采用由两部分组成：持久资料与有效 AGENTS.md 入口，两者都到位才算启用。核对项目根、适用 AGENTS.md／override、已有规范和未提交工作；按实际生效范围合并短段落，保留原有约束和项目约定，只修改项目级指令，全局指令保持原样。已有其他规格体系时，先确认复用或迁移位置。

初始化获授权时按需建立总 `design.md`；留有需后续恢复的设计／计划工作时，按设计参考创建或更新 `handoff.md`——结果报告不能代替 handoff。非 Git 项目也可使用，此时历史只存在于项目文件中。

正式接入时核实 Skill 名称、包根与各能力的可读入口，把下列片段的占位内容替换为真实位置后合并。主入口按需读取 init／design／plan 三个阶段能力，而它们未必与主入口装在一处；登记一个可解析的包根或逐项登记实际入口，后续会话才能直接定位。只能核实主入口时，如实只登记主入口并在本次报告中写明缺口；路径一律填核实过的值。制作未安装包、设计审阅或只读任务只展示片段，不写真实 AGENTS.md：

```markdown
## 使用 fucxxx-codex-spec 开发

本项目采用 fucxxx-codex-spec。涉及设计、计划、实施、复核、恢复或收口时，
即使用户未点名，也使用该 Skill 分流；小修改只核对约束并修改、验证，
design／plan 按需建立。普通问答直接回答。
Skill 入口：<经核实的已安装 SKILL.md 位置或宿主提供的可读取入口>。
Skill 包根：<四个能力目录的共同父目录；各能力不在同一位置时写“无”>。
阶段能力入口：<init／design／plan 的实际位置或宿主可用名称；与主入口同包根时写“同包根”，
  未核实的写“待核实”>。
项目资料根：<相对项目根的实际位置，默认 fucxxx-codex-spec/>。

- 开始相关工作时读 Skill 所需内容，按任务选读现存 handoff、索引、相关 design
  和活动 plan；已有明确派单时直接读指定资料。执行与恢复方法以 Skill 为准。
- 需要阶段能力时按上述登记位置解析并实际读取；读取成功才算已加载，
  解析不到就报告缺口。
- 阶段、范围、基线变化或上下文压缩后，以项目文件和实际状态为准回读相关目标、
  约束和进度，按需选读。
- 遵守用户当前授权：只读任务只报告。入口或资料缺失时说明缺口，继续不受影响的
  授权工作；关键契约不明时暂停受影响实施；安装与重新初始化需要用户授权。
```

只在入口或长期约定变化时更新 AGENTS.md，动态状态写回项目文档；包根或某个能力入口实际迁移时属于入口变化，按维护接入授权更新登记行。入口可能受目录、override 和宿主加载限制影响，要核对实际生效来源。文件存在或 Agent 复述规则都不是执行保证：自动触发是否生效，要观察新会话的实际读取和后续行为才能确认。

文档入口复用现有 README／索引；小项目使用总设计导航区。只写何时读取、链接、简短状态与未验证边界，详细结论以 design 为准。索引只帮助选读；历史或冻结工作要有明确决定才恢复；全局硬约束写进必读位置。

## 结果检查与交回主入口

重复接入时先检查已有段落与资料，只修实际缺口：沿用已有的采用声明、设计结论和状态文件。正式采用不要求先写完产品设计：已有资料直接引用；没有产品背景时，只记录已知目标和明确未知。只为有实际内容或待恢复工作的资料使用主 Skill 的模板建立文件。

检查合并后的指令保留了原约束，主入口可读，登记的包根或阶段能力入口能实际解析到对应 `SKILL.md`，资料路径实际可用且指向项目资料根而非 Skill 包，新建文档的链接能解析。报告时按实际解析结果说明哪些能力可用（登记为“待核实”或“无”的照实列出），并说明实际改动、已有资料的复用关系、仍缺的入口或条件，以及接下来允许做什么。文件检查只证明接入材料有效。

接入后的工作按主入口「阶段衔接」与「提交与外部操作」继续；需要恢复记录时复用同一 handoff。
